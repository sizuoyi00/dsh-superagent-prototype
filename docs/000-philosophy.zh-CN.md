# 000 理念

[English](000-philosophy.md)

dsh-superagent 是一个框架，也代表一种与智能体协作的方式。它的核心原则是：

**尽可能少地占用人的注意力，同时尽可能多地创造价值。**

项目的每一部分都以其占用的注意力来衡量。一条消息、一个通知、一个问题、一项设置、一个面板元素和一段文档都会占用某个人的注意力；每一项带来的价值都必须超过这一成本，否则就应将其移除。

## 由此对智能体提出的要求

- **它只在收到请求或书面规则允许时行动。**只有直接向智能体提出、且来自团队允许人员的请求才算有效请求：请求者要么位于允许列表中，要么属于团队已开放接收请求的对话。对于没有任何人提出的工作，必须有团队编写的规则，并且应从一种只记录智能体原本会做什么的模式开始。
- **它只在有人必须采取行动或可以使用某项结果时发言。**它只确认一次请求，并说明自己将要做什么。工作期间保持安静。只有当结果准备就绪、需要做出决定或无法完成时，它才再次发送消息。消息应简短，并发送到提出请求的原始对话中。
- **它每次只问一个具体问题，**并采用结构化形式，使问题能触达相应人员，而不是埋在一份冗长报告中。
- **它依据影响范围决定在哪里停止，而不是依据投入的工作量。**局部变更应推进到可供评审的结果。需要设计决策的变更应停下来，并提出一个清晰的问题。
- **它如实报告。**草稿会标明尚未完成，失败会如实报告为失败，也绝不会为了避免提问而绕过限制。

## 由此对设计提出的要求

- **概念要少。**设计中只包含领域概念（例如 Source）以及它们的具体实现（例如 GitHub 和飞书）。一项业务需求应成为其中某个概念的属性，或成为智能体遵循的提示词。设计不会为它另加一个概念。
- **设置要少。**当某个值适用于几乎所有团队时，应使用默认值而不是增加一项设置。团队以自然语言描述的行为应写入提示词，而不是做成设置。
- **面板只展示需要人工处理的事项。**面板优先列出等待人工处理的内容。健康状态不占用空间。
- **文档按顺序阅读。**每一篇编号文档都只建立在它之前的文档之上，因此读者永远不需要预先理解尚未介绍的概念。

## 责任

智能体会使用你的团队每天都能看到的账户发表评论、创建 Pull Request 并给人发送消息。它发送的每一条消息都会占用同事的注意力，而你要对此负责。智能体能做的事情越多，操作者就越有责任谨慎对待团队：

- **从小范围开始。**开始时只设置较短的允许列表，并仅记录主动式工作。等到智能体原本会采取的行动看起来符合预期后，再逐步扩大这两个范围。
- **调优以减少噪音。**当智能体产生噪音时，应缩短提示词并让要求更严格，或暂停智能体。不要为了说明噪音而增加更多消息。
- **不要用它批量制造产出。**大量 Pull Request、广播消息和无意义的忙碌给团队带来的成本会超过其价值。
- **对它所说的话负责。**阅读智能体以你的名义发布的内容；当它说错时，在提示词中纠正它。

目标是在恰当的时间提供恰当的帮助，并在其他任何时候保持安静。
